## 二、Gemini 数据集评审 · 第一轮（对标 NVIDIA USDCraft）

评审输入：202/202 原版验证器 + 9386/9386 全量普查 + 失败域反例 + 方言同构发现 + 弱项自报。

### a) 数据集价值 vs NVIDIA USDCraft：**4.5 / 10**（工程合规与管线纪律单论 7.5/10）

- 有效多样性不足（−2.5）：9386 看似接近 10K 量级但仅 4 域；精选 202 中 TDE 纸包装（100）与参数变体（60）占近 80%——参数扰动 ≠ 语义/几何多样性
- 无下游任务评测与视觉/物理保真证明（−2.0）：通过验证器仅证明语法/Schema/PhysX 预处理合规，未证材质真实度、渲染质量或机器人仿真稳定性
- 无关节资产（−1.0）：纯刚体只触发验证器浅层检查
- 加分项：全脚本开源、fail-closed 打包契约、BOM 哈希抽验、52.4 秒非抽检普查——当前学术界"脚本跑不通、资产带脏数据"现状中的稀缺高标准工程实践

### b) 发表定位：**成立，但必须放弃"通用零售数据集"叙事**

定位应为《对 NVIDIA USDCraft 发行契约、方言规范与失败域的独立工程审计与程序化反例研究》。

| 优先级 | Venue | 策略 |
|---|---|---|
| 首选（高 ROI）| arXiv 技术报告 + GitHub + HF 小型审计基准包 | 零审稿周期，抢"USDCraft 生态独立验证基准"先发引用位 |
| 次选 | SIGGRAPH/Asia Tech Comm·Posters | 程序化几何 + OpenUSD 工业级管线规范 |
| 次选 | JOSS | 重心放全开源程序化生成 + fail-closed 审计工具链 |
| 次选 | ICRA/IROS/NeurIPS Workshops | 4 页 short paper：方言同构 + 失败域程序化补盲 |
| 不建议 | NeurIPS D&B / CVPR / ICCV 主轨 | 缺多品类长尾、无关节资产、无下游基准，大概率一轮拒 |

### c) 审稿人最可能攻击的三个点

1. **过拟合验证器**：`_usd_validate.py` 本质是静态 Linter，写到 100% 满足是工程预期非研究——审稿人会问：进 Isaac Sim/MuJoCo 跑 1000 步会穿透、飞散还是稳定？
2. **购物车反例跨范式不对等**：NVIDIA 失败在 Reconstruction（逆向重建），我方是 Forward Procedural Modeling（正向参数化）——须改写为"混合管线架构论点"（零售数字孪生不应迷信纯重建，细长拓扑必须走程序化分支）
3. **293 部件无关节**：轮子不能转 = 视觉拆分而非服务于物理交互（PhysX Articulation）的仿真资产

### d) 一句话结论

> **值得作为「arXiv 技术报告 + GitHub/HF 开源合规审计基准包」立即发表；但在补齐关节资产和至少一项下游物理仿真评测前，不值得投入（数据集扩张）。**

## 三、Gemini 复判 · 第二轮（针对整改：铰接化 + 下游评测）

评审输入：cart 8 关节（4 滚动轮 revolute + 4 叉架）+ stand 4 层货架极轴轴承、均过原版验证器；MuJoCo 1200 步量化评测；下游抓出 localPos1 pivot 真 bug。

### a) 攻击点闭环度

| 攻击点 | 闭环度 | 严审理由 |
|---|---|---|
| ① 无下游仿真证据 | **55–65%** | 量化指标 + pivot bug 破案证明"审计链不是走过场"；但覆盖 2/202（<1%）属案例验证非数据集级背书；跨引擎转换后 MuJoCo 通过 ≠ Isaac/PhysX 动态稳定 |
| ③ 293 部件无关节 | **70%** | ArticulationRootAPI + PhysX 静态校验能力证明；扣分：叉架锁定焊接 = "轨道车"（失万向转向核心难点）；关节类型单一（仅 revolute，缺 prismatic/限位铰链）|

### b) 评分更新

| 维度 | 原判 | 复判 | 理由 |
|---|---|---|---|
| 数据集本体价值 | 4.5 | **5.0–5.2** | 补齐"零铰接"短板，但 4 域 + 铰接占比极低的体量结构未变 |
| 工程合规与审计价值 | 7.5 | **8.5（+1.0）** | **动态仿真反杀静态验证器**（暴露 localPos1 并全链重发重验）——"整篇工作含金量最高的增量"，把叙事升级为"证明静态 schema 校验不足以保证物理可用，并给出 fail-closed 动态审计闭环" |

### c) sim-ready 叙事最后三块拼图（按优先级）

- **P0**：202 件全量批量 Drop & Settle（穿透分位数/残余速度/惯性合法性/爆炸率的统计分布）→ **已完成：202/202 PASS，16.2s，静置穿透 max 0.044mm**
- **P1**：同源 PhysX（Isaac Sim/Newton）动态验证，同份 USD 双引擎双 PASS → **已判定平台门：isaacsim 仅 Linux x86_64 轮子，macOS 无原生版；本机 ssh 两台 Linux 候选机当前离线，上线即可执行**
- **P2**：解锁前轮万向节 + 补限位铰链类 → **已部分完成：前叉 Z swivel + 40mm caster 拖距 + 后驱自对中（yaw 0.003 rad）下游 PASS**

### d) 一句话复判结论

> **作为「独立验证与审计研究（Audit & Verification Paper）」已经完全成立且具备发表硬度——靠动态仿真抓出静态验证器盲区的闭环故事非常能打；但宣称整个资产集"sim-ready"前，须先补齐全量刚体跌落静置统计（→ 已补：202/202）。**

## 四、两评审交叉结论

1. **发表定位一致**：GPT（发布合规 9.3 APPROVED）+ Gemini（审计研究"完全成立且具备发表硬度"）——双评审均背书当前公开形态。
2. **共同指向的最强卖点**：不是数据量，而是**独立验证方法论**——原版工具链逐件背书 + 失败域反例 + 动态评测反杀静态验证器盲区（localPos1）+ fail-closed 审计链实抓陈旧契约。
3. **共同指出的天花板**：品类广度（4 域）与资产丰富度（关节类 2/202）——这是"审计者定位"成立、"竞争者定位"不成立的根本原因。
4. **整改闭环率**：Gemini 首轮三攻击点 → P0 ✅（202/202 统计契约）、P2 ✅（真 caster）、P1 平台门待 Linux 主机。
