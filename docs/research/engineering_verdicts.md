## 一、WP 框架（共识）

| WP | 任务 | 验收目标 |
|---|---|---|
| WP1 | 新商品盲测 | 100 个未见真实 SKU：结构覆盖率与生成成功率（**分母必须是管线未见过的真实商品**；用自产 SKU 盲测=循环论证，已否决） |
| WP2 | **公开数字资产同任务基准测试**（Public Asset Task Benchmark，更名后口径） | 资产级：几何/纹理印刷/USD 结构规范性/物理属性完整性；任务级：同任务仿真表现（统一环境）；**暂不可比**：生成成本、生成成功率、未见商品生成能力（缺对方同口径数据与分母） |
| WP3 | 物理真实性 | 30 个真实商品实测质量/重心/摩擦/典型行为 |
| WP4 | 第三方资产验收 | 提交 SimReady Central；Linux 门只冻结"目标环境实测"，不冻结准备工作 |
| WP5 | 零售业务验证 | 真实陈列/商品中心场景的效率与成本测量 |

WP2 两道门禁：① 配对规则必须在查看质量评分之前冻结（防选择性对照）；② 无法同类同用途配对的资产登记为覆盖差异，不强做质量胜负裁决。

## 二、证据等级（竞品与能力声明统一使用）

E0 检索发现 → E1 文档核验 → E2 实物核验 → E3 运行验证 → E4 独立复现。竞品侦察至少 E2：许可证/商业权限、几何材质碰撞关节质量、GTIN 与商品主数据关联、标准格式独立使用、可复用组件。

## 三、Linux 门语义（共识修正）

Linux 主机是**基础设施依赖，不是研究任务间的逻辑依赖**。冻结的只是"目标环境官方验证器实测与 Isaac 物理仿真实测"；以下工作立即执行：WP4 验收协议设计、USD 静态结构审计、Validator 测试用例准备、Isaac 场景与任务设计。环境未就绪前，任何替代检查**不得标记为"官方验证通过/物理仿真通过"**。不同 Validator 是否必需 Linux 应按工具与版本逐个核实。
